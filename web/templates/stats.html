📊 Compreendendo as Métricas do Sistema

🔢 Métricas de Capacidade e Indexação

Vetores (Embeddings): Representam a capacidade semântica do sistema. Atualmente com {{ "{:,}".format(stats.vectors_count) }} vetores, cada documento regulatório é dividido em trechos menores (chunks) e convertido em representação numérica multidimensional através de modelos de embedding especializados em linguagem jurídica brasileira (Legal-BERTimbau). Quanto maior o número de vetores, mais granular e precisa é a busca semântica, permitindo localizar informações específicas mesmo em regulamentações extensas.

Pontos no Banco Vetorial: Com {{ "{:,}".format(stats.points_count) }} pontos armazenados no Qdrant, esta métrica indica quantos vetores foram efetivamente processados, otimizados e persistidos no banco de dados vetorial. A arquitetura Qdrant organiza esses pontos em estruturas HNSW (Hierarchical Navigable Small World) que permitem buscas de similaridade em tempo próximo a O(log n), garantindo performance mesmo com milhões de documentos.

Taxa de Indexação: A taxa de {% if stats.vectors_count > 0 %} {{ "%.1f"|format((stats.points_count / stats.vectors_count) * 100) }}% {% else %} 0% {% endif %} reflete a eficiência da pipeline de processamento. Uma taxa próxima a 100% indica que todo o conteúdo vetorizado foi corretamente indexado no banco. Taxas inferiores podem indicar processamento em andamento ou necessidade de reindexação. O sistema monitora esta métrica para detectar anomalias no fluxo de ingestão.

📚 Métricas de Cobertura Documental

Documentos por Tipo: O sistema categoriza automaticamente as regulamentações em tipos normativos específicos. Atualmente processados {{ stats.documents.total_processed if stats.documents else 0 }} documentos distribuídos entre Leis e Decretos Federais, Instruções de Comando da Aeronáutica (ICA), Manuais de Comando (MCA), Regulamentos Brasileiros da Aviação Civil (RBAC), Portarias, Resoluções e outros instrumentos regulatórios. Esta categorização permite filtragem semântica e priorização de fontes com base na hierarquia normativa brasileira.

Documentos por Fonte: A rastreabilidade das origens é fundamental para confiabilidade. O sistema integra duas bases primárias:

  • LexML (Legislação Federal): {% if stats.documents and stats.documents.sources %} {{ stats.documents.sources.lexml if stats.documents.sources.lexml else 0 }} documentos {% else %} 0 documentos {% endif %} extraídos do portal oficial do Senado Federal e Planalto, incluindo leis, decretos e medidas provisórias relacionadas à aviação civil brasileira.
  • DECEA (Departamento de Controle do Espaço Aéreo): {% if stats.documents and stats.documents.sources %} {{ stats.documents.sources.decea if stats.documents.sources.decea else 0 }} documentos {% else %} 0 documentos {% endif %} técnicos e operacionais da aeronáutica, abrangendo ICAs, MCAs, circulares e instruções específicas do comando da aeronáutica.

Documentos Originais Preservados: Além dos vetores processados, o sistema mantém {% if stats.documents %} {{ stats.documents.total_originals }} arquivos HTML originais {% else %} arquivos HTML originais {% endif %} baixados diretamente das fontes governamentais. Esta camada de preservação garante auditabilidade, permite reprocessamento com novos modelos de embedding, e serve como backup caso as fontes oficiais sofram alterações ou indisponibilidade.

🔍 Status e Monitoramento

Status do Sistema: O indicador {{ stats.status|upper }} reflete a saúde operacional do banco vetorial Qdrant. Status "HEALTHY" ou "OK" confirma que o serviço está respondendo adequadamente, com latências normais e sem erros de indexação. Monitoramento contínuo 24/7 detecta degradações de performance ou falhas de conectividade.

🔄 Processo de Atualização e Versionamento

Ciclo de Ingestão: O sistema opera em modo híbrido com ingestão incremental automatizada. Scrapers monitoram periodicamente as fontes oficiais (LexML via API e DECEA via web scraping) detectando novas publicações e atualizações de regulamentações existentes. Documentos modificados passam por extração temporal de metadados (datas de vigência, revogação e alteração) garantindo que consultas temporais retornem versões corretas das normas para cada período histórico.

Versionamento Regulatório: Cada documento mantém histórico completo de versões através de campos de metadados temporais (effective_date, expiration_date, modification_date). Esta arquitetura permite consultas do tipo "Qual era a regulamentação sobre X em janeiro de 2023?" - essencial para análises retrospectivas de conformidade e investigações de incidentes aeronáuticos.
